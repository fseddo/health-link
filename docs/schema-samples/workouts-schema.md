# `workouts` — sample rows

User-generated journal data. Soft-delete parent (ADR-002). Idempotent inserts via client-generated `client_id`. Both `started_at` (when the workout happened) and `created_at` (when the row was inserted) — distinct because workouts can be backfilled.

See [`docs/SCHEMA.md`](../SCHEMA.md#workouts) for the full column list.

## Columns

`id`, `user_id`, `routine_id`, `title`, `started_at`, `ended_at`, `notes`, `client_id`, `created_at`, `deleted_at`

UNIQUE `(user_id, client_id)`. Index `(user_id, started_at DESC) WHERE deleted_at IS NULL`.

## Notes

- **Backfilled workout `w-4`**: `started_at` is 2026-05-09 (the actual session) but `created_at` is 2026-05-15 (six days later when the user logged it). This is exactly why both timestamps exist — ML features like "lag-to-log" need them.
- **In-progress workout `w-3`**: `ended_at` NULL means the session is still active. The mobile client can keep adding sets until the user taps "finish."
- **Soft-deleted workout `w-5`**: `deleted_at` set. All its child `workout_exercises` and `sets` still exist physically — they're filtered out at query time via the JOIN to `workouts.deleted_at IS NULL`.
- **Idempotency**: `client_id` is generated by the client before the network call. Re-sending the same POST returns the existing workout (200 or 409 depending on intent) instead of creating a duplicate. UNIQUE `(user_id, client_id)` enforces this at the DB.
- **Two "Push A" rows** (`w-1` and `w-4`) — same title is fine; titles aren't unique. The `client_id` is what identifies a specific session. Both rows link to the same `routine_id = 'r-push-a'`, which is what lets the progression ML group them as "Push A sessions" rather than string-matching the title.
- **`routine_id` is nullable** (`w-6`). Ad-hoc workouts with no template are first-class. `title` is independent of routine — it's a free-text snapshot, can match the routine name, diverge from it (e.g. "Push A — light day"), or be set without a routine at all.
- **Title vs routine name**: `title` is captured at workout creation and frozen. If the user later renames `r-push-a` to "Push Day Heavy", `w-1.title` still reads "Push A". This is intentional — the journal records what the session was called *at the time*.
